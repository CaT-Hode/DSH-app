# Agent Note: Combine accounting, plugin pages and desktop appearance

Status: implemented

Cost and usage owns one same-origin document scroll area. A session-maybe child slot portals current-session context into its accounting document, retaining the official session projection and locale providers. The all-session overview selects one period and owns the cumulative cost, Token and call cards; current-session context retains pressure, estimated composition, request history, tool statistics and activity. Changing the period leaves budget and price drafts intact.

The rail exposes Settings directly, puts Automations near the top, and removes Recent chats and the separate MCP entry. Plugins contains Browse, Skills and MCP. Browse combines the catalog, uncatalogued installs and official optional features through All, Installed, Updates and Available filters. Official configuration retains injected services, store and authorized slots; its uninstall callback queues stopped-profile work and opens the unified restart notice. Official activation notices remain visible in Browse. Skills uses owned UI and authenticated routes. Existing skill files and manager policies remain available through official root and agent providers, with model and command invocation states shown separately. Edits use revisions, removals use recoverable trash, and imports stage bounded files without replacing existing skills. Disposal restores decorated components and removes provider registrations.

MCP uses an owned React UI with DSH theme and font tokens. Its MIT Host engine derives from Connector 0.2.63 and preserves the existing storage domain, grants, policies, scopes, snapshots and managed entry identifiers. Authenticated routes whitelist methods and enforce current Host origins. An enabled predecessor retains sole storage ownership until removal. The MIT Sidebar 0.24.1 runtime is mounted inside DSH App, preserving viewer/tab contributions, per-session targets, native right-sidebar integration and the public module aliases. Its editable preferences belong to the parent's sidebar settings field; lazy editor and Mermaid chunks remain bounded routes. Licenses and pinned provenance accompany both engines.

The market is owned by DSH App. Retired integrations are excluded from discovery and cannot be installed alongside their owned replacements. Catalogs and registry metadata load on demand with bounded requests and an explicit stale-cache state. Install, update and removal requests are durable metadata, never mutations of a running module graph. The desktop stops its backend, backs up dependency and activation metadata, invokes the supported profile CLI and verifies the actual installed version and activation. Queues clear and success is reported only after the replacement backend is ready. Failed batches retain diagnostics and backup recovery. Updates preserve the previous enabled state. The update-provider v1 read APIs remain available for MCP; their capabilities explicitly direct mutations to the built-in market rather than presenting a queued update as already installed.

Package metadata and its title and description are optional. Browse invokes the official locale resolver only for supplied values; missing text falls back to the catalog or package name. The released resolver requires a string or language map, so passing undefined crashes the main slot. The regression check loads the supported DSH locale runtime and renders absent, partial and localized metadata. Client metadata explicitly orders the shared UI primitives and remote providers before the embedded sidebar runtime.

The native controls are 30 DIP high within a 38 DIP client titlebar. Loading and failure pages read the current profile's ui-theme.preference without evaluating JavaScript YAML tags. Electron nativeTheme resolves light, dark or system before first paint. Loaded pages send both the official preference source and resolved color; switching fixed dark to system dark must update nativeTheme even when colors match, and live values take precedence over a pending persistence write. No backend or network request is needed to choose startup colors.

Focused checks cover the accounting period and editing drafts, session projection and portal ownership, official installed management, owned skill navigation and mutations, authenticated market routes, stopped-profile changes and recovery, MCP catalog artwork, appearance changes and both startup palettes. Real Electron acceptance validates the installed artifacts and page behavior separately.
