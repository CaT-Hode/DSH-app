# Integrated sidebar engine

This directory retains the MIT licensed runtime of `dsh-better-sidebar@0.24.1`, from [omdsh-dev/DSH-better-sidebar](https://github.com/omdsh-dev/DSH-better-sidebar). The source artifact hashes are recorded in `upstream-hashes.json`; the copyright notice is retained in `LICENSE`.

`index.mjs` is the published Host artifact. Its settings row resolves to DSH App, and preference reads and writes use DSH App's `sidebar` field through `../settings.mjs`. The original `/sidebar` API, filesystem checks, WebSocket upgrades and session state remain in place. `client-factory.mjs` is the published browser factory with its registration wrapper removed and its documented registry functions exported. It is integrated into DSH App's single client module. Public browser aliases and `ctx.betterSidebar` remain available to existing contributors.

The editor, Mermaid and optional locale integration stay separate lazy scripts. The redundant standalone registry bundle, original sources, tests, build tools and unrelated package documentation are not retained. The engine uses DSH's native right sidebar and terminal. DSH App owns the surrounding layout, fonts and colors.

The Mermaid and locale lazy scripts and license retain their original bytes through repository attributes. The editor lazy script includes a minimal owned CodeMirror line-navigation effect. The hash manifest records the original published inputs rather than hashes of these modified files. Only the published editor and Mermaid bundles exempt original trailing spaces from Git whitespace checks; those spaces include template-string content. Owned source and other files retain ordinary whitespace checks.

The integrated client contains exceptions from contributed registry and session-state subscribers so one failing subscriber does not prevent native tab synchronization, another subscriber or contribution disposal. Callback failures retain the engine's existing error reporting.

The engine no longer contributes its original Side card settings page or navigation icon. Activation returns its preference resources to DSH App, whose owned General settings UI edits the same revision-protected settings and retains dynamic tab, viewer and extension declarations. Shell-path guidance points to General settings.

The owned `client/sidebar-workbench.css` replaces the predecessor's visual presentation with the app's Codex tokens across workbench bodies and native tab chrome. The bridge temporarily disables predecessor custom and preset skin sheets, preserving functional layout and title-strip measurements and restoring those sheets on disposal. `client/sidebar-workbench.mjs` contributes the session header launcher and a sandboxed HTTP(S) preview when the Web profile has no native browser.

The client adapter now preserves folder/title/line navigation, initializes browser URLs, focuses actual native tabs, retains full close-callback metadata, and replays pending opens in FIFO order. Synthetic native records follow their native AbortSignal, navigation revisions distinguish new opens from rerenders, and visited bodies stay mounted to retain editor drafts and Side Chat state. Independent page types retain their multiple-instance contract. DSH App removes the predecessor bottom drawer and its geometry/toggle effects, redirects legacy bottom-open requests to the native right sidebar, and migrates persisted tabs after confirmed native placement. Unavailable extension tabs remain in their restoration backlog.

Native view bindings now persist bounded, whitelisted navigation fields separately from the official layout, keyed by parent session and occurrence and validated against its exact resource address and kind. Restored revision-zero navigation keeps the selected file path/title/line, preview URL and Side Chat thread binding; explicit subsequent navigation replaces them. Live records and title/body subscriptions use the same parent-session scope because native occurrence IDs repeat across sessions. Chrome/service closes remove their binding, while client disposal retains it for reload. Transcript bodies, agent keys and arbitrary extension metadata are excluded. Side Chat pending seeds stay durable until thread binding, then move into the independent draft/reference cache and remain consumed after sending.

`client/sidebar-sidechat.mjs` adds searchable history, thread naming, explicit context references, independent persisted drafts, and answer-to-main-chat actions around the original Side Chat transcript and composer. Minimal factory hooks allow this owned wrapper to reuse streaming, reasoning, tool cards, subagent context and the original Host protocol. Fetch errors surface with retry; asynchronous responses are fenced to the active thread; send/stop operations guard duplicate clicks; closing a tab during creation releases the abandoned child. Completed-turn promotion uses the official `uiWorkspace` navigator and retained session rename API, and reuses an existing promotion of that completed turn. Visible beta labels are removed. The tab registry adds reversible `replaceTab` ownership without resurrecting disposed contributions.

`../agent-control.mjs` and `client/sidebar-agent.mjs` add authenticated, session-owned commands and acknowledged state without modifying the upstream filesystem or Git endpoints. Side Chat agent commands stage a draft and context or reopen an owned thread; they do not submit a prompt. Rendered regression fixtures exercise the original Side Chat API wire calls and CodeMirror editor, including thread creation, isolated draft/context restoration, failed send preservation, cancellation, transcript retry, native migration and main-chat promotion.
